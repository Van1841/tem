PRODUCT PURPOSE
WebWin helps a company's sales team discover businesses that may be potential customers for website development.
The V1 workflow is:
Location + Business Category → Google Places → Filter businesses without a listed website → MongoDB → Display leads
The important business rule is:
If Google Places does not provide a websiteUri for a business, treat it as a potential lead.
This does NOT prove that the business has no website. It only means that Google Places did not provide/list a website.

V1 SCOPE — ONLY BUILD THIS
User logs in.
User enters a location.
User enters a business category.
Backend searches Google Places API.
Backend receives matching businesses.
Businesses with a listed website are ignored.
Businesses without a listed website are normalized and saved to MongoDB.
Duplicate businesses are prevented using Google Place ID.
Saved leads are fetched from MongoDB and displayed in the dashboard.
Search statistics are shown after each search.

LEAD FILTERING
For every Google Places result:
If websiteUri exists:
Do NOT save the business.
If websiteUri does not exist:
Save it as a potential lead.
Use:
websiteStatus: "not_listed"
Do NOT label it:
"No Website"
"Website Missing"
"Website Doesn't Exist"
because Google Places not providing a website does not prove that the business has no website.

DEDUPLICATION
Google Place ID is the primary unique identifier.
Create a unique MongoDB index on placeId.
Rules:
Same placeId found in another search → skip it.
Different placeId → treat it as a different business.
Do NOT use placeId + name as the primary uniqueness rule.
Different nearby businesses can have similar names, so Place ID must remain the primary identity.
Handle duplicate insert attempts gracefully without crashing the search.
